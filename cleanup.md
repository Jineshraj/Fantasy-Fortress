**Scope:** repository files, application source, scripts, documentation, configuration,
ignored local artifacts, and current untracked work.  
**Action taken:** analysis and planning only. **No files were deleted.**

## 1. Important safety warning

- 26 tracked files are modified.

## 3. Proposed cleanup levels

Use these levels when executing the cleanup later:

- **Level A — disposable local artifacts:** safe to remove locally after confirming the app is not
  being served from the directory. These are regenerated or tool-owned.
- **Level B — likely obsolete files:** good deletion candidates after checking external deployment,
  hosting, and operator usage.
- **Level C — archive or consolidate first:** historical records or scripts that may contain
  operational context. Do not permanently delete them until the useful context is retained.
- **Level D — preserve:** current authority, runtime code, deployment configuration, credentials
  templates, active tests, or files referenced by current application code.

## 10. Suggested execution order

When the owner is ready to perform cleanup:

1. Review and commit or separately branch the current modified/untracked application work.
2. Confirm the deployed client is built from source and not directly served from `client/dist/`.
3. Remove/reinstall dependency and build directories locally as needed (Level A).
4. Check external imports, hosting references, and operator runbooks for the orphan service and
   placeholder assets (Level B).
5. Archive one-off scripts and historical Markdown before deleting anything (Level C).
6. Decide the root npm/lockfile strategy before touching `package-lock.json`.
7. If deleting the ignored local test harnesses, update package scripts and README commands in the
   same change.
8. Make one focused cleanup commit, run the smallest meaningful checks, and inspect the diff.

## 11. Pre-deletion checklist

- [ ] Current Git changes are reviewed and no active untracked source is mistaken for debris.
- [ ] No candidate is imported, required by `package.json`, referenced by deployment config, or
      invoked by an external scheduler/runbook.
- [ ] Google Sheets/Supabase state affected by one-off scripts is confirmed and any needed history
      is retained.
- [ ] Important scoring, security, deployment, and UI decisions from historical Markdown are
      retained before documents are archived/deleted.
- [ ] Credentials have not been copied into reports or commits.
- [ ] Client build dependencies are healthy before using a build as a regression check.
- [ ] After cleanup: `git diff --check`, client build, and the relevant client harnesses are run.

## Final recommendation

The safest cleanup is **not** a bulk delete. First remove only disposable local artifacts, then
archive historical reports and one-off operational scripts. The only high-confidence source/config
deletions are the unreferenced `tournamentCalendarService.js`, stale `client/components.json`, and
verified placeholder assets—after their guards pass. Preserve current scoring authority, live-data
code, deployment files, credentials templates, active tests, branding, and the audit context until
the project owner explicitly approves its archival replacement.
